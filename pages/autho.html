Authentication & Authorization

Uygulama güvenliğinin iki temel bileşeni

Authentication (Kimlik Doğrulama) ve Authorization (Yetkilendirme), uygulama güvenliğinde birlikte çalışan iki temel kavramdır. Bu iki kavram, hem kullanıcıların kim olduğunu hem de hangi işlemleri yapmaya yetkili olduklarını belirler.

🔑 Authentication

Kimlik Doğrulama, bir kullanıcının gerçek kimliğini doğrulama sürecidir. Amaç, "Bu kişi gerçekten kim olduğunu iddia ettiği kişi mi?" sorusuna cevap bulmaktır.

Örnek Senaryo:

  • Kullanıcı giriş ekranına kullanıcı adı ve şifre yazar
  • Sistem bu bilgileri kontrol eder
  • Bilgiler doğruysa kullanıcı doğrulanır

Yaygın Yöntemler:

Parola (Password)

En yaygın kullanılan kimlik doğrulama yöntemi

Token (JWT, API Key)

Web ve mobil uygulamalarda sık kullanılır

Biometrik

Parmak izi, yüz tanıma gibi fiziksel doğrulama

2FA / MFA

İki veya çok faktörlü doğrulama ile ek güvenlik

Özetle: Authentication = "Kimsin?" sorusuna verilen cevaptır.

🔐 Authorization

Yetkilendirme, kimliği doğrulanmış bir kullanıcının hangi kaynaklara erişebileceğini belirleyen süreçtir. Yani kim olduğunu biliyoruz, şimdi ne yapabileceğine karar veriyoruz.

Örnek Senaryo:

  • Kullanıcı giriş yaptı (Authentication tamam)
  • Ancak sadece "Admin Paneli" sayfasına girmeye yetkili olan kişiler var
  • Sistem, kullanıcının rolüne bakarak izin verir veya reddeder

Yaygın Yöntemler:

RBAC

Role-Based Access Control - Kullanıcı rolleri üzerinden yetki

ABAC

Attribute-Based Access Control - Kullanıcı özellikleri değerlendirilir

PBAC

Policy-Based Access Control - Belirli politikalar uygulanır

Özetle: Authorization = "Ne yapmaya yetkilisin?" sorusuna verilen cevaptır.

⚙️ Temel Farklar

Özellik Authentication Authorization
Amaç Kullanıcının kimliğini doğrulamak Kullanıcının yetkilerini belirlemek
Zamanlama Önce gerçekleşir Authentication'dan sonra gerçekleşir
Veri Kaynağı Kimlik bilgileri (şifre, token) Rol veya izin bilgileri
Sonuç Kullanıcı sisteme giriş yapar Kullanıcı belirli işlemleri yapabilir
Örnek Giriş yapma (login) Admin paneline erişim izni

🔒 Gerçek Hayat Örneği

Bina Güvenlik Sistemi Benzetmesi:

Authentication: Kapıdaki güvenlik kartını okutur ve içeri girebilirsin. (Kimliğin doğrulandı)

Authorization: Ama sadece senin katına çıkabiliyorsun; yönetici katına çıkamazsın. (Yetkin sınırlandı)

🌍 Modern Uygulamalarda Kullanım

  • Web uygulamalarında JWT (JSON Web Token) en yaygın yöntemdir
  • API'lerde, genellikle Bearer Token veya API Key tabanlı sistemler kullanılır
  • Bulut servislerinde (AWS, Azure, GCP) rol tabanlı yetkilendirme (RBAC) standarttır
  • Mikroservis mimarilerinde her servis kendi yetkilendirme mantığını uygulayabilir

💡 Kod Örneği - ASP.NET Core

[HttpPost]
public async Task Login(LoginModel model)
{
  // Authentication: Kullanıcı kimliğini doğrula
  var user = await _userService.Authenticate(model.Username, model.Password);
  if (user == null) return Unauthorized();

  // JWT Token oluştur
  var token = _jwtService.GenerateToken(user);
  return Ok(new { Token = token });
}

[Authorize(Roles = "Admin")] // Authorization: Sadece Admin rolü
[HttpGet("admin")]
public IActionResult AdminPanel()
{
  return Ok("Admin paneline hoş geldiniz!");
}

🎯 Sonuç

Authentication ve Authorization, birlikte bir güvenlik zinciri oluşturur. Authentication kimliği doğrular, Authorization ise o kimliğe sınırlar koyar. Bu iki süreç birlikte kullanıldığında, sistem hem güvenli hem de kontrollü hale gelir.

Modern uygulama geliştirmede bu iki kavramı doğru şekilde implemente etmek, güvenlik açıklarını önlemede kritik öneme sahiptir.
